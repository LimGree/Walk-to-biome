СПЕЦИФИКАЦИЯ: сценарии соединения и поворота на сетке
Проект: Walk-to-biome (Unity, FPS factory-builder)
Ориентир: поведение как в Builderment / Satisfactory, но в нашей архитектуре.

════════════════════════════════════
0. ЧТО УЖЕ ЕСТЬ (не ломать)
════════════════════════════════════
- GridSystem + GridOccupancy (словарь клеток)
- BuildingSocket: connectedBelt + connectedSocket
- AutoConnector: соседи + направления (dot)
- ConveyorPlacement.Resolve: straight/corner при Place ленты
- ConveyorBelt: Straight / Corner, start/mid/end, GetEntry/ExitDirection
- PlayerBuilder: ghost, R на ghost, demolish ПКМ, Build Mode по B
- Прямое building↔building уже работает

════════════════════════════════════
1. БАЗОВЫЕ ПРАВИЛА (обязательно)
════════════════════════════════════
- Всё на квадратной сетке (1 клетка = 1 unit).
- У здания явные Input/Output сокеты (не центр модели).
- У ленты есть направление потока (Entry → Exit).
- Соединение создаётся ТОЛЬКО если:
  • Exit одного смотрит на Entry/Input другого, ИЛИ
  • Output здания смотрит на Entry ленты / Input соседнего здания.
- Нет «магического» соединения бок о бок без совпадения направлений.

════════════════════════════════════
2. СЦЕНАРИИ СОЕДИНЕНИЯ КОНВЕЙЕРОВ
════════════════════════════════════

2.1 Торцевое (конец в конец)
- Новая лента: Entry смотрит в Exit уже стоящей (или наоборот).
- → nextBelt / prev, предметы едут дальше.
- Форма: обычно Straight.

2.2 Боковое (поворот)
- Ставишь ленту так, что поток должен повернуть на 90°.
- → ConveyorPlacement выбирает Corner + правильный yaw/mirror.
- Предметы едут start→mid→end.

2.3 Уже стоящая Straight + новое здание сбоку
- Сценарий: лента уже стоит, ставишь здание с Input, смотрящим на эту ленту.
- → Лента ДОЛЖНА перестроиться в Corner (reshape), exit на Input здания.
- Предметы: по возможности сохранить; если сложно — ClearItems + лог.

2.4 Уже стоящая Straight + новая лента сбоку
- Аналогично: если поток логично поворачивает — reshape в Corner.

2.5 Две параллельные ленты рядом
- НЕ сливаются. Нужен отдельный splitter (позже) или ручной поворот.

2.6 Крест-накрест / underground
- В ЭТОЙ ФАЗЕ НЕ ДЕЛАТЬ.

2.7 Здание поверх ленты
- В ЭТОЙ ФАЗЕ НЕ ДЕЛАТЬ (не ставим здания на занятую клетку).

════════════════════════════════════
3. СЦЕНАРИИ ЗДАНИЕ ↔ ЛЕНТА / ЗДАНИЕ
════════════════════════════════════

3.1 Здание сбоку от ленты
- Если Input здания смотрит на Exit ленты → соединение + при необходимости reshape ленты в Corner.
- Если направления не совпадают → соединения нет.

3.2 Здание торцом к ленте
- Output здания → Entry ленты или Exit ленты → Input здания — классический AutoConnector.

3.3 Здание вплотную к зданию
- Output ↔ Input через connectedSocket (уже есть) — сохранить.

════════════════════════════════════
4. ПОВОРОТ (R)
════════════════════════════════════

4.1 Ghost (ещё не поставлено)
- R крутит ghost на 90°.
- Для Conveyor: Resolve может пересчитать straight/corner от нового yaw.

4.2 Уже размещённый объект (НОВОЕ — обязательно)
- В Build Mode, меню закрыто: луч на объект + R.
- Объект поворачивается на месте на 90° БЕЗ сноса.
- Конвейер:
  - Меняется yaw (и при необходимости shape через Resolve/reshape).
  - Пересчитать связи AutoConnector.
  - Предметы на этой ленте: ClearItems (допустимо) или сохранить progress.
- Здание:
  - Крутится модель + все сокеты.
  - DisconnectAll старых связей → AutoConnector.TryAutoConnect заново.
  - Внутренние буферы зданий НЕ очищать.
- Multi-select / Undo / Move mode — НЕ в этой фазе.

4.3 После поворота
- GridOccupancy: Unregister → Register с новым rotated size (для зданий >1x1).
- Соседи: soft-refresh / TryAutoConnect.
- Если после поворота направления не совпадают — связи просто отсутствуют (не крашиться).

════════════════════════════════════
5. RESHAPE УЖЕ СТОЯЩЕЙ ЛЕНТЫ (ключ)
════════════════════════════════════
Вызывать после Place здания или ленты (и после rotate на месте):

Для каждой соседней клетки placed-объекта:
  если там ConveyorBelt:
    пересчитать оптимальный shape/yaw для ЕЁ клетки
    если нужно стать Corner (или сменить ориентацию):
      заменить префаб (straight↔corner), сохранить cell, data
      OnPlaced + AutoConnector
      items: сохранить или ClearItems

Нельзя оставлять старый GO в GridOccupancy.

════════════════════════════════════
6. ЧЕГО НЕ ДЕЛАТЬ В ЭТОЙ ФАЗЕ
════════════════════════════════════
- Splitter / Merger / T-junction с zipper-merge
- Underground belts
- Здание поверх конвейера
- Multi-select, Undo стек, Move mode
- FindObjectsByType (только GridOccupancy)

════════════════════════════════════
7. КРИТЕРИИ ПРИЁМКИ
════════════════════════════════════
1) Лента → лента торец: поток идёт.
2) Лента ставится с поворотом к зданию: сразу Corner.
3) Сначала Straight, потом здание сбоку с Input на ленту: лента становится Corner и отдаёт в здание.
4) R на ghost крутит; R на уже стоящем здании/ленте крутит на месте и пересобирает связи.
5) Demolish освобождает клетку; нельзя ставить в занятую (красный ghost).
6) Прямая цепочка лент не превращается в Corner без причины.
